# ADR-0011: Approval workflow configuration is validated JSON data, resolved by a fixed vocabulary
**Date:** 2026-10-20
**Status:** Accepted (feature approval-workflows)
**Context:** PRD Module 13 requires configurable workflow definitions (trigger, conditions, ordered/parallel steps, approver resolution, SLA, delegation) with versioning and instance binding to an exact subject revision. The PRD and AGENTS.md both forbid tenant-supplied executable JavaScript as workflow configuration. A naive implementation might let tenants upload code or expression strings evaluated at runtime, which would be an arbitrary-code-execution and privilege-escalation surface.
**Decision:** A `WorkflowVersion.rules` payload is declarative JSON validated against a strict shape whitelist. Each step names a `resolver` only from a fixed set (`ROLE`, `REPORTING_MANAGER_OF_REQUESTER`, `REPORTING_TREE_OF_REQUESTER`, `NAMED_EMPLOYEE`, `PERMISSION`), a `mode` from `all|any`, and numeric `minApprovals`/`amountThresholdCents` (integer cents). No field is ever evaluated as code (`eval`/`Function`/template expressions are never used). Unknown resolver/mode/keys, negative or non-integer thresholds, or string values that look like expressions are rejected at publish time. Subject amount is supplied as validated `subjectContext` **data**, not computed by executing tenant config. Instances pin the `workflowVersionId` at start; in-flight instances are not migrated when a version is retired.
**Rationale:** Keeping configuration as data preserves tenant configurability while eliminating the code-execution and privilege-escalation surface; pinning versions makes approvals reproducible and auditable (an approval is bound to the exact reviewed revision).
**Consequences:** New resolvers require a code change plus a validator update (acceptable; heuristic/scripted routing is out of scope). Version migration of in-flight instances is deferred. Verified by unit tests (rule-shape validator rejects executable-looking input) and smoke tests (bad rule publish → 400; unknown subject type → 400).
